<p>Detecting threats in a Kubernetes cluster can be challenging, we generally don't know where and how to start.
The good news is that we have an amount of valuable logs that can help us to know what is happened in the cluster. Indeed, each action requested or done by a user or an app, in a cluster, is recorded in Audit Logs.
Kubernetes events are key to understanding the behavior of a cluster.</p>
<p>We already provide plugins that let you parse Audit Logs and use Falco to detect threats from GKE, EKS and AKS clusters. With our latest plugin, you'll now have the same powerful threat detection capabilities for your OVHcloud MKS clusters 🎉.</p>
<h2 id="what-is-falco">What is Falco?</h2>
<p>Falco is an Open Source cloud-native runtime security tool. It provides near real-time threat detection for cloud, container, and Kubernetes workloads by leveraging runtime insights. Falco can monitor events from various sources, including the Linux kernel, and enrich them with metadata from the Kubernetes API server, container runtime, and more.</p>
<p>Falco can receive <strong>Events</strong>, compare them to a set of <strong>Rules</strong> to determine the actions to perform and generate <strong>Alerts</strong> to different endpoints.</p>
<h2 id="what-is-the-ovh-mks-audit-logs-plugin">What is the OVH MKS Audit Logs plugin?</h2>
<p>The OVH audit logs plugin (<a href="https://github.com/falcosecurity/plugins/tree/main/plugins/k8saudit-ovh">k8saudit-ovh</a>) extends Falco's capabilities to OVHcloud Managed Kubernetes Service (MKS) clusters, providing you with the same security insights and threat detection Falco already offers for GKE, EKS and AKS environments.</p>
<p>With this plugin, you can seamlessly integrate MKS Audit Logs into Falco's event processing pipeline, enabling it to identify anomalies, suspicious activities, and policy violations within your MKS-based workloads.</p>
<p>Concretely, when a user executes some <strong>kubectl</strong> commands in an OVHcloud MKS cluster, Audit Logs will be generated. Falco is listening to them, and depending on the configured rules to follow, it will generate some alerts.</p>

<h2 id="using-ovh-mks-audit-logs-plugin">Using OVH MKS Audit Logs plugin</h2>
<p>In order to use the OVH MKS Audit Logs plugin, you must follow several steps:</p>
<ul>
<li>deploy an OVHcloud LDP (Logs Data Platform)</li>
<li>create a data stream into this LDP</li>
<li>connect an OVHcloud MKS cluster to the data stream (to send Audit Logs into it)</li>
</ul>
<p>To be able to access our Kubernetes clusters' Audit Logs, you need to deploy an <a href="https://www.ovhcloud.com/en/identity-security-operations/logs-data-platform/">LDP</a>. LDP is the managed platform for collecting, processing, analyzing, and storing your logs of the OVHcloud products. Deploy an LDP (Bare Metal Cloud universe) with whatever plan you want.</p>
<p>OVHcloud Kubernetes Audit Logs will be stored in a data stream. The OVHcloud Audit Logs Falco plugin receive the audit logs through Websocket so you need to enable <strong>Websocket broadcasting</strong> when you create the data stream on LDP.</p>
<p>Retrieve the Websocket URL, follow <a href="https://help.ovhcloud.com/csm/en-ie-logs-data-platform-ldp-tail?id=kb_article_view&amp;sysparm_article=KB0055757#retrieve-your-websocket-address">the guide</a> to do so.
The Websocket address have this kind of format: <strong>wss://gra.logs.ovh.com/tail/?tk=</strong></p>
<p>Finally, you have to <a href="https://help.ovhcloud.com/csm/en-public-cloud-kubernetes-forwarding-audit-logs?id=kb_article_view&amp;sysparm_article=KB0062285#enabling-audit-log-forwarding-using-the-ovhcloud-control-panel">connect a MKS cluster to the LDP data stream</a>.</p>
